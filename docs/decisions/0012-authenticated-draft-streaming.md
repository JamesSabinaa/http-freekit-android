## Actual wire and fixture controls

The separate research listener implements `/companion/v1/control` and `/companion/v1/streams` against the unchanged normative [appendix](../protocol-streams.md). Registry-authorized mutual TLS precedes either route. Stream upgrades require the exact bounded `X-FreeKit-Session` header bound to that authenticated device and its active control owner. Reject browser Origin, cookies, generic Authorization, duplicate critical headers, query strings, unsupported extensions/subprotocols, malformed WebSocket keys/version and unrecognized routes before admitting a stream. Bound HTTP headers, pre-authentication sockets and upgrade work independently of model leases.

Use the new pull-based research WebSocket implementation. Do not attach unbounded flowing message callbacks. Serialize model operations, but never hold the model lock across a blocking socket write: control cancellation and deadline expiry must still be able to close the underlying stream socket. Apply fresh UTC and monotonic clocks on every operation. Do not fake a model message, drain or closure observation to satisfy a test.

Trusted device IDs are `dev_` plus canonical base64url SHA-256 of the authenticated client SPKI, computed independently on each side. The paired desktop ID is the fixed public fixture value `research-desktop`. Control supports only actual `tcp-http` and `tcp-https-connect`. Generate session IDs with a CSPRNG. Ordinary readiness expires after approximately 120 seconds; the expiry scenario uses 30 seconds. Use the codec's exact second-resolution UTC form and real clocks, without changing the device clock or rebasing UTC to a peer-supplied epoch. The new driver requires a measured device/host skew within 2000 ms and a clock-probe round trip within 2000 ms; a failing preflight is a real setup failure, never a successful skip. Existing certificate/probe limits are not changed.

The compatible device probe uses whole-second `date +%s`. Accept only when its entire possible skew interval, `[deviceSeconds * 1000 - hostAfterMillis, deviceSeconds * 1000 + 999 - hostBeforeMillis]`, fits within the two-second skew bound. Record both endpoints as well as the midpoint estimate and round trip. A midpoint alone can understate real skew by the quantization and sampling uncertainty; it cannot establish this profile.

Negotiate 4096-byte binary messages, 8192 bytes/stream, 16384 bytes/device, two concurrent streams, four queued frames and 64 opened IDs. Use shared trusted pool limits of four sessions, eight streams and 65536 bytes. These bound application ownership, not TLS/kernel/native or total-process memory. Research framing's 64-fragment/control guards remain explicit limitations. Send/observe control ping/pong at most 10 seconds apart; stream activity cannot replace control liveness.

Research-only HTTPS `/research/probe` and `/research/command` may coordinate the synthetic fixture. They require the same authorized mTLS device, session header and owner binding. Commands are a bounded enum for fixed gates such as releasing upload/response tails, pausing/resuming the fixed proxy reader, or observing premature closure. A bounded research-scenario header on the control upgrade selects `gated`, `backpressure`, `cancel`, `expiry`, `binding`, `malformed` or `premature`. No client-provided destination, URL credential, file, shell command or arbitrary byte-generating expression is accepted. Return only bounded fixed counters/booleans/enums, never keys, session tokens or traffic in default diagnostics. Agree the precise command/probe schema between the two owners before their adapters depend on it.

The only command bodies are the exact compact UTF-8 literals `{"command":"release_response_tail"}` and `{"command":"resume_proxy_read"}`, without a newline, capped at 128 bytes with exact Content-Length and application/json. The latter is allowed only for the backpressure scenario. GET probe has no body/query and returns at most 4096 bytes. The periodic real deadline owner, not a probe's snapshot read, handles expiry. ## Socket and model ownership

An owned loopback TCP socket pair on Android represents the native/application byte-stream seam. Its producer writes upload bytes and performs a real output half-close; its consumer receives response bytes and observes EOF. The Android adapter bridges that socket to WSS. On Node, the gateway connects only to one owned fixed loopback proxy fixture. Use half-open sockets so request EOF leaves the response direction usable. This is not VPN routing or real desktop proxy integration.

Accepted data stays charged until the actual local writer returns/completes and any required drain finishes. Retain at most one unaccepted bounded message while paused; retry that same message after space is available. Emit typed directional `end_write` only after preceding bytes finish writing. Proxy/application socket half-close effects must likewise follow actual drain. Do not buffer whole requests/responses. Use bounded generated chunks, incremental digests and fixed expected lengths. The burst fixture may generate at most 32 MiB while reusing bounded chunks; failure to observe actual outstanding I/O within that budget fails the test rather than claiming backpressure.

Record writer entry/completion separately and observe a genuinely unfinished write/callback with retained bytes before testing cancel or expiry. A timeout alone is not proof of a blocked writer. On Android retain the owned underlying raw socket through the existing TLS factory's `rawSocketFactory` seam. Close that raw socket to interrupt blocked SSL I/O before any potentially blocking TLS close; keep the original scoped trust and key manager. Join readers, writers, fixture sockets/acceptors and heartbeat/deadline workers, then confirm model resource closure. Node must await actual transport close and pending write callbacks. Resource counts remain charged while cleanup is incomplete. A cleanup timeout fails; it cannot count as completed closure.

Framing failures close transport before forwarding bytes and can produce an abnormal model transport-close outcome; malformed application JSON is processed by the actual codec/model. Never fabricate JSON to translate a framing error. Normal completion requires both actual directional EOF effects, empty queues, close1000 and confirmed joined resource closure. Every scenario finishes with zero owned leases/bytes/workers or explicitly fails cleanup.

Either real clock owner may reach the expiry deadline first within the measured two-second skew profile. Require at least one actual deadline-driven `session_expired` cause, both owners inactive and streams failed rather than complete, and a genuinely outstanding charged write before expiry. The other owner may first observe `network_unreachable` from the peer's real close. Its deadline worker must run and join, but need not win this race. If its model has already expired, do not inject a post-terminal typed disconnect or predate an operation. The cancellation case separately proves the Android owner's raw-socket interruption.

The read-only probe includes a fixed `timing` object with `readyUtcMillis`, `expiresUtcMillis`, nullable `terminalUtcMillis` and nullable `terminalElapsedMillis`. Capture terminal timing once at the first actual terminal transition; elapsed time starts at accepted readiness. A local expiry cause requires terminal UTC at or after expiry, or actual monotonic elapsed at least the accepted lifetime. Android records the corresponding public readiness/expiry, observed UTC/elapsed and remaining lifetime. An expiry observed through the peer may precede Android's own UTC deadline only within 2100 ms (the measured bound plus 100 ms observation margin). No clock is changed or rebased, and reading the diagnostic snapshot cannot advance the model.

Before expiry-case joins, Android sends exactly one status-code-2 research observation, independent of the seven ordinary start/end pairs. It contains version `1` and 13 fixed `draftExpiry`-prefixed timing, tick and boolean fields defined by the [result parser](../../tools/transport-spike/draft-stream-results.mjs). Require this exact bundle while the expiry case is active; reject duplicates, unknown fields, noncanonical numbers/booleans, inconsistent lifetime, impossible early observations or absence of either actual deadline proof. Local expiry ticks can be zero when another fresh-clock model operation wins the deadline race; the deadline worker must still have run. Peer terminal UTC/elapsed are paired nullable values and must establish the deadline when the peer is the reported winner. Retain these public observations as XML/HTML properties after cleanup, so auditors can inspect actual runtime timing without raw instrumentation logs.

## Required Android cases

The new class is `com.httpfreekit.interop.DraftStreamingInteropTest`. Its exact methods are:

1. `authenticatedControlAndGatedStreamPreserveHalfClose`: actual mTLS control hello/readiness and separate bound stream open/ready. The fixed proxy must observe upload prefix before the producer releases its tail; it must observe actual request EOF before releasing response prefix. Android's consumer must receive that prefix before response tail is released. Verify ordered bytes/digests, both EOFs, close1000 and cleanup.
2. `boundedBackpressureResumesWithoutDroppingBytes`: pause the actual proxy reader, observe charged model data and one bounded pending ingress message, then resume it. Verify actual writer completion, ordered byte count/digest and normal EOF/closure without dropping or replaying bytes.
3. `cancelClosesAnObservedBlockedWriterAndJoinsResources`: prove a stream writer is entered and unfinished against the non-reading fixture, cancel through the independent live control/local owner, close real raw sockets, observe I/O termination and join before releasing model charges.
4. `expiryClosesAnObservedBlockedWriterAndJoinsResources`: repeat using actual session expiry and owned deadline processing; no synthetic clock jump. Retain charges until observed termination and cleanup.
5. `wrongSessionAndDeviceBindingAreRejected`: wrong token and another enrolled device's certificate cannot open a stream belonging to the first device; existing active owner/resources remain intact. Exactly one additional identity is allowed, for at most eight issuances in the seven-case run.
6. `malformedAndOversizedIngressFailBeforeForwarding`: exercise bounded invalid application JSON and invalid/oversized WebSocket headers using research-only adversarial writes. The established writer must not be weakened to send invalid data. Prove no offending bytes reach the fixed proxy and no premature resource release or successful completion.
7. `prematureCloseCannotCompleteStream`: an actual transport close before the required EOF/drain sequence fails the owner, never reports complete, and still joins/releases real resources.

Each case owns and deletes its Keystore identity and sockets in `finally`. The new driver/verifier must require exactly seven actual starts/completions with terminal success, no duplicate/unexpected/skipped cases, verified ADB channel and actual selective cleanup. Reports may retain fixed counters, timings, resource states and synthetic digests only. Existing four-method and native/Keystore gates remain separate. API 26/37 execution, physical networks, production enrollment/registry policy, VPN/protected sockets and full protocol freeze are not inferred from local compilation or mocks.

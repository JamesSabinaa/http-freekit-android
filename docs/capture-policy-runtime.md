# Capture owner and real TUN policy

C1 implements the missing packet path after the [verified enrollment research](validation.md#android-enrollment-https-runtime). It creates `core-capture` and a separate Android research host/traffic fixture. The production app remains a simulation until capture policy, transport composition and v1 freeze are verified. This package must deliver executable capture code and actual selected-UID traffic evidence, not another protocol model or issuer framework.

## Ownership and interfaces

Root owns root/module build configuration, reusable pinned native build support, library manifest and `CaptureVpnService`. UI owns other `core-capture` sources/tests. F owns `tools/capture-spike/` host and traffic applications, their build/manifests, instrumentation and one standard Ubuntu/KVM API 26/37 workflow. D owns the internal desktop HTTP attachment in its separate desktop worktree. The board records branches and commits. No local emulator retry, production wire integration or signing-material upload is authorized by this profile.

`com.httpfreekit.capture.InterceptedTcpFactory` is per-session and AutoCloseable. `open(originalAddress: InetAddress, originalPort: Int): CaptureTcpConnection` receives only numeric IPv4/IPv6 and port 80 or 443. The connection exposes input/output streams, `shutdownOutput()`, `interrupt()` and `close()`. Factory close seals admission, interrupts pending opens and active transports, and joins its owned workers independently of the caller's relay threads. Connection close confirms its own actual transport joins. No direct fallback or DNS resolution of an intercepted destination is permitted.

`ProtectedEgressFactory` owns every raw TCP/connected UDP socket before any fallible setup. It requires successful VPN protect, then underlying `Network.bindSocket`, then connect. A narrow injectable socket-guard interface permits refused-protect/failed-bind tests without replacing the actual socket or reporting fake Android API results. Failure closes the raw socket and never tries an unprotected/unbound alternative. It also exposes a scoped fresh raw SocketFactory for later TLS composition. Close seals admission and interrupts all owned sockets, including pending connects.

Construct and retain `CaptureEngineSession` before calling its fallible `start()`. It owns the real TUN descriptor, private configuration, local policy listener, native lease, egress and intercepted factories. One live native lease is permitted per process. Reject empty app selection and second live owners. Startup failure remains owned until actual cleanup. `failClosed()` seals traffic and joins native/Java I/O while retaining the TUN route; explicit `close()` additionally closes that descriptor after native Stop really joins. An unresolved Stop retains the native lease, descriptor and configuration and refuses restart. A timeout, interrupt or cancelled future is not a join.

The shared session limit is 32 owned flows/sockets, with at most eight UDP targets per authenticated association, 8192-byte TCP relay chunks, bounded numeric-address headers and UDP payloads up to 65507 bytes. Handshake/connect deadlines are at most five seconds; idle/session deadlines are finite. Track current sockets, workers, pending opens and actual native state/joins in an immutable primitive snapshot. Counters contain no destinations, packages, configuration, credentials or payload. Release charges only after actual closures/joins.

## Native and policy path

Reuse the exact pinned Hev source, MIT/BSD notices, NDK 28.2.13676358, API-26 ARM64/x86_64 builds and 16 KiB alignment. Generalize the existing project-authored build helper with validated JNI package/class and purpose while preserving the old probe defaults. The new class is `com/httpfreekit/capture/NativeEngine`; upstream sources stay unchanged.

Bind SOCKS only to device loopback. Generate fresh unpredictable username/password per engine lifetime, keep them in private memory/configuration and disable native debug/payload logging. Require RFC 1929 authentication before any egress allocation. Use the pinned engine's local UDP-in-TCP mode (`udp: tcp`, command 5): each frame has BE16 payload length, exact numeric header length 10/22, ATYP/address/port and payload. This is engine-to-app local transport only. Do not expose an unauthenticated UDP relay or race to pin the first local datagram source.

TCP 80/443 goes exclusively to the intercepted factory. Other TCP goes directly through protected, network-bound sockets. UDP/443 is dropped before egress allocation; other UDP, including DNS, uses bounded connected protected/network-bound sockets per distinct numeric target. Serialize UDP responses on their authenticated TCP association. Apply the same policy to IPv4 and IPv6; preserve original addresses, bytes and directional EOF. DNS stays on the underlying network; no synthetic map-DNS or desktop DNS is added.

## VPN service and research control

`CaptureVpnService` is an abstract reusable service. Its concrete research subclass supplies a `CaptureStartRequest` containing nonempty selected packages and an intercepted factory. Root and UI finalize the small constructor/snapshot spelling directly without another report-contract prerequisite. Before establish, verify consent, installed allowed packages, exclusion of the companion itself and a non-VPN underlying network. Use only Builder allowed-app mode, routes for both address families, MTU 1500 and underlying-network DNS. Empty allowlists must never establish an all-app VPN.

Run service/native setup and Stop on an owned lifecycle worker. Start foreground promptly with a visible notification and explicit immutable Stop action. Handle `onRevoke`, destruction and network loss. While capture remains requested, loss/failure retains the TUN route and fails intercepted traffic closed; explicit Stop restores normal networking after actual joins. Never replay requests. No production pairing/connection UI is activated by this research package.

For target SDK 37, declare and check the [Android local-network permission](https://developer.android.com/privacy-and-security/local-network-permission) before starting this capture mode. The controlled traffic APK also declares it for its private host-alias targets. Record actual runtime grants and refusal before TUN/native start; do not lower target SDK, substitute loopback routing or silently fall back to evade the platform boundary. Older APIs retain their existing permission behavior.

The traffic APK exposes only a signature-permission protected explicit bound Messenger service with finite command IDs and synthetic fixed payloads. The research host and fixture use the same owned debug signing identity. Result replies contain only fixed counts/digests/status, are bound to the owned request and never expose an arbitrary socket/destination service. Public numeric test ports may be supplied through private fixture input; no credentials enter arguments or reports.

Use controlled receivers accessible through the emulator's host alias. HTTP80/HTTPS443 and UDP53/443 listeners are owned test resources; detect collisions and fail rather than displace listeners. On the fresh hosted runner only, an explicit unprivileged-port setup may permit these fixed port roles. Selected traffic reaches an independently counted intercepted receiver; the same traffic UID outside a second nonempty allowlist must reach the direct receiver. Do not use an empty allowed-app list as bypass evidence. IPv6 intercepted original destinations may use a controlled transport receiver in either family while retaining exact original IPv6 metadata.

F's five common methods are `selectedTcpUsesTunAndNonselectedUidBypasses`, `directTcpUdpDnsAndUdp443Policy`, `selectedIpv6UsesTun`, `stopJoinsCaptureAndAllowsFreshStart`, and `protectAndBindFailuresFailClosed`. API 37 first runs `localNetworkDenialPreventsTun` with real VPN consent but denied local-network permission, requiring the fixed permission failure, no factory/TUN/native startup and actual Stop/join. The owned driver then grants local-network permission before the common methods; API 26 has no corresponding permission/denial claim. Require real TUN establishment and original bytes, positive direct UDP/DNS controls before UDP443 no-delivery plus policy-drop evidence, missing/wrong local auth with zero egress, actual Stop/native/worker/FD joins and fresh restart. Per-flow protect/bind refusal happens after TUN startup and must prevent that flow's connect; do not invent an assertion that no VPN had started. Record actual consent/revocation/network-loss observations separately; a test injection cannot become a real platform event. Keep artifacts bounded and sanitized, reuse owned commands, and do not introduce a general evidence framework.

## Desktop HTTP attachment

D implements internal `proxy.attachTrustedHttpStream(duplex, {originalAddress, originalPort, authorizeDestination, signal}) -> {closed, close()}`. Copy the trusted context into private state; do not encode identity or destination authority in a forwarded header. Use Node's HTTP parser and existing capture/streaming/rule paths for raw origin-form HTTP and OPTIONS*, with one valid bounded Host. Host can choose the logical capture URL, but cannot retarget the physical original numeric destination. Tests may use ephemeral original ports; any later companion HTTP80 adapter must restrict the research target to port 80.

The initial attachment is direct-only. Fail closed for upstream-proxy delegation, cross-origin rules or secondary webhook network targets unless an exact numeric endpoint is separately authorized and pinned at actual network admission. Preserve ordinary proxy behavior outside this trusted context. Cover streaming/chunking, keepalive/Host isolation, upgrades/coalesced head, same-origin transform/forward/breakpoint behavior, denied/malformed ingress, actual destination admission, abort and delayed reply after request write EOF. No new listener or management route is added.

The raw injected seam is a local interface, not the current draft explicit-proxy wire. Before composing it over companion WSS, root must explicitly version/document the proposed original-IP CONNECT80/plain-HTTP attachment behavior and communicate it across repositories. Existing absolute-form HTTP/CONNECT443 and all current conformance fixtures remain valid. Do not promote the old literal fixture rewrite into a general HTTP implementation or claim this package alone freezes v1.

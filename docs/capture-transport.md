# Authenticated capture transport implementation

Status: C2 research implementation is in progress. Shared HTTP-origin wire handling, the maintained WebSocket owner, factory startup/cleanup and actual JVM enrolled-factory-to-desktop HTTP exchange pass host checks. Android runtime acceptance remains open. The implementation uses the existing `InterceptedTcpFactory`/`CaptureTcpConnection` path. The [HTTP origin extension](protocol-http-origin.md) is the new wire rule. C1's reproduced cold EOF reset remains an explicit limitation, without further guessed framework changes.

## Maintained WebSocket engine

Use pinned Java-WebSocket1.6.0 (MIT), published JAR SHA256 `eae29213e4f16515639c28957200f011b3967fffcada1962cf0255d24919c22f`, through its public `WebSocketImpl` engine. SLF4J API and NOP provider are pinned to2.0.20, the [stable Java8-compatible release](https://www.slf4j.org/news.html). No stock WebSocketClient, hidden socket/thread machinery, TRACE backend, compression or subprotocol is used. Before feeding any traffic, require the actual SLF4J factory to be NOP; do not change global TLS or logging settings. Default object/exception output must omit endpoints, credentials, headers, provider material and payloads.

Root authorizes a narrow pre-engine envelope guard for this isolated implementation. It retains at most14 frame-header bytes and counters, validates server role (unmasked), zero RSV, legal/minimal lengths, per-frame limits and finite fragmentation, then feeds the original validated bytes unchanged to the maintained engine. It does not implement payload decoding, masking, UTF8, handshake acceptance or close semantics. Text messages are at most16384 bytes, binary messages at most65536 bytes, and fragmented messages at most128 fragments including empty fragments. Reject excess before engine allocation. The draft subclass overrides copyInstance and processFrame, delegating maintained RFC processing after project limits. Bound the initial HTTP upgrade through CRLFCRLF to4096 bytes before decode; following bytes enter the envelope guard. Reject presence of Sec-WebSocket-Protocol or Sec-WebSocket-Extensions in the public client-handshake callback. Client masks remain the engine's SecureRandom output.

Source boundaries were verified against the [official release](https://github.com/TooTallNate/Java-WebSocket/releases/tag/v1.6.0), [engine](https://github.com/TooTallNate/Java-WebSocket/blob/v1.6.0/src/main/java/org/java_websocket/WebSocketImpl.java), [draft](https://github.com/TooTallNate/Java-WebSocket/blob/v1.6.0/src/main/java/org/java_websocket/drafts/Draft_6455.java) and [published POM](https://repo.maven.apache.org/maven2/org/java-websocket/Java-WebSocket/1.6.0/Java-WebSocket-1.6.0.pom). Stock translation loses incoming mask evidence and accepts nonminimal lengths; its queue/default handlers alone do not satisfy this contract. Guarding those specific gaps is not a claim that stock behavior passes our wire rules.

## OwnedGatewayWebSocket API

Create pure JVM module `:gateway-websocket` at tools/transport-spike/gateway-websocket, package `com.httpfreekit.transport.websocket`. Constructor arguments are an already validated/handshaken SSLSocket, a trusted idempotent `interruptRaw: () -> Unit`, HTTP authority, fixed control/streams path, and nullable session header. Construction is inert; caller retains raw/TLS ownership before fallible start. Authority is bounded ASCII without CRLF; paths are only `/companion/v1/control` and `/companion/v1/streams`; control has no session header, streams require the canonical32-byte/43-character header. No research scenario header is accepted.

The concrete class exposes:

| Operation | Contract |
| --- | --- |
| `start(deadlineNanos: Long)` | Start owned reader/writer and wait for validated upgrade; one absolute System.nanoTime deadline, failure interrupts raw I/O but still requires actual join. |
| `writeText(text: String, deadlineNanos: Long)` | Bounded complete text; return only after actual TLS write and flush, never on engine send/queue removal. |
| `writeBinary(bytes: ByteArray, deadlineNanos: Long)` | Copy bounded nonempty binary; same actual completion rule. |
| `writePing(deadlineNanos: Long)` | Empty RFC ping with the same actual write/flush receipt; engine automatic pong remains enabled. |
| `pollIncoming(waitMillis: Int): Incoming?` | Wait0–1000ms; null is an observation timeout, not terminal. Incoming is Text, Binary, Ping, Pong or Closed(normal:Boolean). Ping/Pong expose no payload; text/binary access is explicit and all default toString output is redacted. |
| `requestClose()` | Queue one normal close after prior writes, without claiming completion. |
| `interrupt()` | Seal admission, wake blocked queues/receipts and close raw I/O without needing engine/model locks; no join claim. |
| `awaitJoined(deadlineNanos: Long): Boolean` | Observe actual reader/writer termination and successful owned closure within deadline; false retains unresolved ownership. |
| `close()` | Idempotent interrupt/actual join with a fixed bounded cleanup budget; throw a fixed safe cleanup failure if unresolved, retain handles for retry. |
| `snapshot()` | Inert immutable counts/flags/fixed failure code only, including reader/writer liveness, pending bytes/slots and actual join. |

Two explicit I/O workers maximum per backend. Reader calls use at most8192-byte buffers. The engine is serialized; synchronous onWriteDemand drains its public queue immediately into bounded owned output, never into an unbounded executor. Queued plus in-flight output is at most8 slots/131072 bytes, charged through actual write+flush completion. Incoming is at most2 messages/131072 bytes plus one bounded decode in progress; queue pressure pauses reader progress and cancellation wakes it. No callback, queue-empty check, cancelled future or socket-close request counts as worker join or writer acknowledgement. Enforce operation deadlines without holding locks across blocking I/O. Own every timer/task if used; close/join it too. Do not block interruption on an engine/model lock.

Meaningful tests include actual independent Node/TLS interoperability, fragmented text/binary, mask/minimal-length/RSV/extension/header/fragment-count rejection, actual blocked write interrupted and joined, queued-input cancellation, close ordering, finite byte ownership and secret-free failure output. Android compatibility and factory/session behavior remain separate gates; a JVM adapter pass is not an Android certificate/protect/bind proof.

The exact1.6.0 engine decode method ignores frame input after locally entering CLOSING, and its eot can report1000 from only the local close request. After the bounded HTTP upgrade, use the public copied draft's translateFrame/processFrame methods for envelope-validated frames, including CLOSING. Keep maintained payload/UTF8/close validation. Closed(normal=true) requires an actual valid received Close frame with code1000, not merely a local request or EOF. Preserve received application messages before Closed. Deterministic tests cover both peer Text-before-Close and peer EOF without a Close frame.

A completed write receipt remains valid when its actual TLS write/flush finished within the deadline and a subsequent validated normal close finished the I/O workers before the caller resumed. Explicit interruption, any latched operational/cleanup failure, unfinished writes and late flushes still fail. An internal immutable caller-scheduling hook, inert through the unchanged public constructor, makes this ordering deterministic in actual TLS tests. The original implementation failed the normal-close case while the cancellation case passed; the unchanged two tests pass after the fix. The complete backend suite is now25 cases and also passes with SLF4J2.0.20.

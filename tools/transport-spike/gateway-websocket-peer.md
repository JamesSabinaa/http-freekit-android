# Maintained WebSocket backend test peer

This is the finite independent Node/TLS test interface for the JVM backend in [the capture transport contract](../../docs/capture-transport.md). It proves backend framing/I/O only. It does not claim Android certificates, saved credentials, VPN protect/bind or an authenticated desktop gateway.

The new `gateway-websocket-peer.mjs` CLI accepts exactly `--scenario NAME`; Node and the existing OpenSSL3 prerequisite supply its implementation environment. It listens on an owned ephemeral IPv4 loopback port. Certificates/private keys are generated in one owned private TEMP directory; only public gateway DER and logical name are published. The client must construct its own scoped validated SSLSocket using that metadata. No global trust or logger changes are allowed.

The frozen scenario names are `echo`, `fragmented`, `queued-input`, `held-read`, `bad-mask`, `bad-rsv`, `bad-minimal16`, `bad-minimal64`, `oversized-frame`, `fragmented-byte-limit`, `empty-fragment-count129`, `header-limit`, `bad-extension`, `bad-subprotocol`, `invalid-utf8`.

`echo` handles bounded text/binary, ping/pong and normal close. `fragmented` sends valid fragmented text/binary with ping interleaving. `queued-input` sends three bounded binary messages then holds. `held-read` pauses real TCP/TLS input after validated upgrade so the client must demonstrate actual blocked output interruption. Malformed cases send one fixed violation without provider/payload diagnostics; frame lengths/header bytes remain deliberately bounded on the sender. All scenarios use only the two fixed companion control/streams paths; streams require a canonical session header, control requires none. The peer does not require client authentication: backend tests begin with an already validated TLS socket, and the later factory proof owns real mTLS/registry authorization.

Fixed payloads: `fragmented` sends UTF8 `fragmented-€-backend` in byte fragments [0:12], [12:14], [14:end], splitting the Euro encoding. It then sends binary4097 bytes `(i*29+3)&255` in fragments [0:1024], [1024:1025], [1025:end]. An unmasked ping with ASCII payload `probe` follows the first fragment of each message. This scenario does not echo extra application data. `queued-input` sends three binary messages of65536 bytes; message j=0,1,2 contains `(i*17+j)&255`, then holds. `held-read` sends no application frames and consumes no post-upgrade TCP/TLS input before release. Echo compares text/binary byte-for-byte. On the first actual client Ping it writes the matching Pong, then exactly one server Ping with payload `probe`; later client Pings receive only their matching Pong. No server Ping precedes the client's first Ping. Binary input remains bounded to65536 bytes;65KiB is an oversize rejection, not an accepted operation.

Stdout is private test IPC, bounded JSON lines. Ready is exactly `{format: "http-freekit-gateway-ws-peer", revision: 1, event: "ready", port, logicalName, gatewayCertificateDer}`. Port is 1–65535; DER is canonical base64url, at most4096 decoded bytes. No key, path, bearer/session header or request body enters output.

Stdin accepts only the exact compact ASCII lines `{"op":"release"}` and `{"op":"stop"}`, each followed by LF. Bound each line to1024 bytes, all input to8192 bytes and at most8 commands. One release resumes the held scenario and emits exactly `{format, revision: 1, event: "released"}`. Stop closes admission, interrupts/joins actual sockets and tracked tasks, closes the listener and removes the owned private directory. EOF/disconnect/signals also invoke owned cleanup; malformed/duplicate operations fail with fixed diagnostics and still clean up. There is one fixed60-second scenario deadline, not reset by progress.

Final stdout is exactly `{format, revision: 1, event: "closed", admissionClosed, listenerClosed, activeSockets, pendingCallbacks, pendingTimers, workers, ownedChildrenJoined, privateDirectoryRemoved, upgrades, clientTextMessages, clientBinaryMessages, clientPongs, clientCloseObserved}`. Flags are booleans; counts are bounded nonnegative integers. Success requires actual resource counts0 and admissionClosed/listenerClosed/ownedChildrenJoined/privateDirectoryRemoved true. clientCloseObserved is diagnostic and may be false after deliberate interruption. Normal diagnostics/toString/JSON are redacted; explicit public metadata and finite IPC are the only material access. Test parents must join the actual child process and stdio, not merely receive this acknowledgement. No runtime report or Android acceptance is synthesized by this peer.
